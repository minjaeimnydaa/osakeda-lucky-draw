# 별도 개선 버전

현재 버전은 `lucky-draw`, 개선 버전은 `lucky-draw-v2`에 있습니다. 소스와 DB, 보안 키, 로그인 쿠키를 각각 분리했습니다. 기존 당첨·이메일·참여 기록은 복사하거나 변경하지 않았습니다. 두 버전의 이벤트 날짜와 참여 상태는 서로 독립적입니다.

- 현재 버전: http://localhost:3000/?event=lucky-days
- 개선 버전: http://localhost:3001/?event=lucky-days
- 개선 버전 실행: 이 폴더에서 `node server.js`
- 로컬 미리보기: 실제 경품 지급 없음. 새 테스트 코드 `OSAKEDA-TEST-01`~`03` 사용 가능.

## 이번에 반영한 개선

| 발견한 문제 | 개선 버전의 동작 |
|---|---|
| 이메일을 등록하지 않은 당첨자도 참여 완료로 보임 | 메인 버튼을 ‘수령 이메일 등록하기’로 표시. 등록 후 발급 대기, 운영자의 발급 처리 후 발급 완료로 구분 |
| 모바일 첫 화면에서 참여 버튼이 아래에 잘림 | 본문 버튼이 충분히 보이지 않을 때만 하단 참여 버튼 표시. 본문 버튼이나 입력창이 보이면 하단 버튼 숨김 |
| 모바일에서는 경품 정보를 보려면 아래로 내려가야 함 | 추첨 제목 아래에도 1등 혜택과 전체 당첨 인원을 간단히 안내 |
| 집게의 타이밍·티켓 위치가 당첨에 영향을 주는 것처럼 보임 | 뽑기 버튼 바로 아래에 위치와 관계없이 무작위로 추첨한다는 안내 추가 |
| 코드를 못 받은 고객이 어디서 도움을 받을지 알기 어려움 | 코드 입력창에 확인 방법과 스토어 문의 경로 추가. 운영자가 설정한 문의처도 표시 |
| 종료·소진·일시 중지에도 ‘내일 참여’처럼 읽힐 수 있음 | 서버 시간을 기준으로 다음 한국 시간 자정을 계산. 실제 다음 참여일이 있을 때만 시간 안내 |
| 코드 확인이나 이메일 등록은 성공했지만 새로고침만 실패하면 실패로 보임 | 확인된 성공은 유지. 코드 확인 재시도는 조회만 실행하고, 이메일 등록 성공은 화면에 남김 |
| 세션이 만료되면 이메일 입력창에서 막힘 | 참여 코드 재확인 버튼 제공. 같은 당첨 내역으로 돌아오면 작성 중인 이메일과 동의 유지 |
| 통신 장애 시 영문 오류나 무한 대기 가능 | 한국어 오류와 상태 재확인 버튼 제공. 불확실한 추첨은 저장 결과를 확인하기 전 재추첨 차단 |
| 공유 이미지에 예전 녹색 병 디자인이 남아 있음 | 현재 화면과 같은 단순한 파란색 병·잔 형태 적용 |

기존 집게 형태와 모션, 사케 일러스트, 경품 행의 등수 칩과 전체 색상은 유지했습니다. 추첨 확률·재고 제한·1일 1회 규칙·이벤트 중 최대 1회 당첨 규칙은 변경하지 않았습니다. 공유 주소와 이미지에는 이메일이나 참여 코드를 넣지 않습니다.

## 다음에 검토할 요소

1. **구매 고객 코드 자동 전달:** Shopify 구매 확인 후 코드 발급·전달을 연결하면 수동 운영과 문의를 줄일 수 있습니다. 이번 버전에는 연결하지 않았습니다.
2. **경품 발급 자동화:** 현재는 이메일 수집 후 운영자가 발급합니다. 실제 기프트카드 생성·전송·실패 재처리는 별도 연동이 필요합니다.
3. **이메일 정정과 운영 이력:** 수령 주소 수정 요청, 수정 이력, 이메일 미등록 당첨자·미발급 건 필터를 추가하면 운영이 쉬워집니다.
4. **실제 행사 전 부하 검증:** 동시성 검증은 로컬 테스트입니다. Vercel·운영 PostgreSQL에서 예상 접속량을 검증한 뒤 필요한 속도 제한과 대기 처리를 결정해야 합니다.

## 확인 방법

`node --test test/*.test.js`로 추첨·인증·쿠키 분리·수령 단계·한국 시간 자정·통신 오류·성공 후 조회 실패 복원·세션 재확인을 검증합니다. 브라우저에서 모바일 하단 버튼, 코드 도움말, 입력 오류와 자동 정규화, 공유 이미지도 확인했습니다. 원본 보존 여부는 `baseline-hashes.json`과 원본 파일의 SHA-256 값을 비교해 확인합니다.
