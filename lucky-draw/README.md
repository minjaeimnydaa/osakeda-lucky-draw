# 오사케다 럭키 드로우

구매 고객용 참여 코드로 응모하는 외부 이벤트 사이트입니다. Shopify 연결과 기프트카드 발송은 수동으로 진행합니다.

고객 화면은 선물 안내와 집게 뽑기로 구성되며, 모바일에서는 뽑기를 먼저 표시합니다. 코드 확인·행운 뽑기·결과 확인의 진행 상태를 표시하고, 공유 이미지는 미리보기에서 확인한 뒤 저장할 수 있습니다.

뽑기 기계는 네이티브 SVG와 Web Animations로 좌우 이동·하강·집기·상승을 표현합니다(`public/claw.css`, `public/app.js`). 버튼을 누르면 현재 집게 위치에 해당하는 티켓 번호(1~9)를 서버에 전송하며, 위치와 당첨 확률은 관계없습니다. 동작 중에는 코드 변경과 재클릭을 잠그고, 동작 줄이기 설정에서는 이동을 생략합니다. 재접속 시 저장된 결과만 표시하며 뽑기를 재생하지 않습니다.

고객 전용 테마(`public/sake.css`)는 오사케다의 실제 로고와 토스 GUI를 참고한 회색 배경·둥근 흰 카드·큰 고딕 글씨·파란 주요 버튼을 적용합니다. 상단은 제목·설명·일정과 단순한 사케 병·잔 일러스트로 구성합니다. 1·2·3등 칩은 각 경품 행의 우측 상단에 유지합니다. 경품은 기프트카드이며 관리자 스타일과 추첨 정책에는 영향을 주지 않습니다.

브랜드 참고: https://osakeda.com/ (2026-10-28 확인). 로고와 Nunito 400/700/800은 공식 스토어에서 확인한 자산을 로컬로 보관합니다. 로고 원본: `https://osakeda.com/cdn/shop/files/v2_1b7f6fdf6dd949647a071e120518e819_RLQUUEA9_top_500x.png?v=1704421779`. Nunito의 SIL Open Font License는 `public/fonts/OFL-Nunito.txt`에 포함합니다. UI는 기기의 고딕 글꼴을 우선 사용합니다.

UI 참고: https://tossmini-docs.toss.im/tds-mobile/foundation/typography/ · https://tossmini-docs.toss.im/tds-mobile/components/button/ . 시각적 원칙을 참고했으며 토스 로고·전용 글꼴·라이브러리를 사용하거나 토스 연동을 제공하지 않습니다.

## 로컬 실행

Node.js 24 이상에서 이 폴더를 연 다음 실행합니다. 로컬 실행에는 패키지 설치가 필요 없습니다.

```sh
node server.js
```

- 고객 화면: http://localhost:3000
- 관리자 화면: http://localhost:3000/admin
- 관리자 비밀번호: 첫 실행 시 생성되는 `.env.local`의 `ADMIN_PASSWORD`
- 로컬 테스트 코드: `OSAKEDA-TEST-01`, `OSAKEDA-TEST-02`, `OSAKEDA-TEST-03`
- 기록은 `.data/events.sqlite`에 저장됩니다. 로컬은 테스트 표시가 항상 붙고 실제 경품이 발급되지 않습니다.
- 관리자에서 테스트용 코드를 추가 발급하거나 이벤트를 복제할 수 있습니다. 테스트 확률은 참여 전에 조정하세요.

검증: `node --test test/*.test.js`

## Vercel에 공개하기

1. 이 폴더를 비공개 GitHub 저장소에 올립니다. `.env.local`, `.data/`는 절대 올리지 않습니다.
2. Vercel에서 저장소를 연결합니다. 상위 폴더를 올렸다면 Root Directory를 `lucky-draw`로 지정합니다. Framework는 Other, Node.js는 24.x, Output Directory는 `public`입니다. 빌드 명령은 필요 없습니다. 의존성은 Vercel이 설치합니다.
3. Neon 또는 Supabase 등 관리형 PostgreSQL을 만들고 TLS가 설정된 서버용 연결 문자열을 준비합니다. `DATABASE_URL`에 입력합니다. DB 접속은 서버에서만 합니다. Supabase를 쓸 경우 Data API 공개 테이블과 분리된 전용 DB 사용자/스키마를 권장합니다.
4. Vercel 환경 변수에 `DATABASE_URL`, `SESSION_SECRET`(32자 이상 무작위 값), `ADMIN_PASSWORD`(16자 이상 강한 비밀번호)를 설정합니다. SESSION_SECRET을 바꾸면 세션이 만료되고 고객 해시가 달라지므로 진행 중 변경하지 마세요.
5. 배포 후 `/admin`에서 로그인합니다. 운영 DB에는 테스트 코드 없는 **준비 중** 이벤트가 별도로 생성됩니다. 경품과 확률은 기본 샘플이므로 실제 지급할 경품으로 수정하세요.
6. 발급 일정, 문의처, 개인정보 수집 주체·항목·목적·보관 기간·거부 안내를 입력합니다. 기간과 수량을 확인한 뒤 공개 상태로 저장합니다. 보관 기간 만료 후 개인정보 삭제는 운영자가 DB에서 처리해야 합니다.
7. 구매 내역에서 고객별 고정 식별값(Shopify customer ID 권장)을 준비해 관리자에서 코드를 발급합니다. 코드는 CSV로 한 번만 내려받을 수 있습니다. 다운로드 실패 시 같은 화면의 다시 저장 버튼을 이용하세요. CSV에는 고객 식별값과 원본 코드가 있으므로 비공개로 보관합니다.
8. 구매자에게 자신의 코드만 전달하고, 오사케다 팝업에는 관리자에서 연 이벤트 전용 주소를 연결합니다.

실제 Vercel 배포와 PostgreSQL 검증은 계정 및 연결 정보가 있어야 마칠 수 있습니다. 현재 프로젝트에는 이 연결 정보가 포함되어 있지 않습니다.

## 추첨·재고 처리

- 위치에 경품을 숨기지 않고, 서버의 암호학적 난수로 추첨합니다. 선택하지 않은 카드의 가상 당첨 결과를 표시하지 않습니다.
- 각 등수의 확률을 0~100%로 설정합니다. 전체 합은 100% 이하입니다. 경품 5개가 모두 당첨된다는 보장은 없습니다.
- 소진된 등수의 확률은 미당첨으로 처리합니다. 모든 경품이 소진되면 신규 추첨을 마감합니다.
- **1차 버전은 전체 기간 재고 방식입니다. 날짜별 배정·이월·종료 후 추가 추첨은 구현하지 않았습니다.**
- PostgreSQL의 이벤트 행 잠금, 응모 기록과 재고 조회의 동일 트랜잭션, 고객별 일자 UNIQUE, 고객별 당첨 UNIQUE INDEX로 중복과 초과 당첨을 막습니다.
- 한 고객의 여러 코드는 같은 고객 해시로 묶습니다. 서로 다른 식별값을 입력하면 같은 고객으로 인식할 수 없으므로 주문 번호를 고객 ID 대신 쓰지 마세요.
- 카드 재클릭/여러 탭/재접속은 기존 결과를 반환합니다. 당첨자는 이후 날짜에도 새로 추첨하지 않습니다.
- 당첨 이메일은 동의 후 한 번 등록합니다. 오기입 정정은 고객센터에서 신원을 확인한 뒤 DB에서 처리합니다. 코드 소지자가 수령 정보를 등록할 수 있으므로 코드의 개별 전달이 중요합니다.
- `발급 완료`는 관리 상태만 바꾸며 기프트카드 생성/이메일 전송 기능이 아닙니다.

## 운영상 범위

- 전용 행 잠금으로 정확성을 우선합니다. 한 이벤트의 추첨 쓰기는 직렬 처리되므로, 대규모 행사 전 실제 배포 환경에서 예상 피크 부하를 검증하고 DB 연결 수/리전/요금제를 결정하세요. 대규모 트래픽 대응이 검증된 상태는 아닙니다.
- DB 스키마는 첫 요청 시 자동 생성됩니다. 서버 DB 사용자는 해당 스키마에 테이블·인덱스 생성 권한이 필요합니다.
- 관리자 인증: HttpOnly 서명 쿠키, 동일 출처 요청 검사, DB 기반 로그인/코드 시도 제한. HTTPS는 Vercel에서 제공합니다.
- 기간·경품 설명·확률은 응모가 발생한 뒤 잠급니다. 전체 수량은 기당첨 수량 이상으로만 변경할 수 있습니다.
- 새 이벤트 복제 시 설정만 복사합니다. 코드·참여·당첨·이메일 기록은 복사하지 않습니다.
- 일반 공유창/링크 복사와 1080×1920 스토리 이미지 저장을 제공합니다. 인스타 스토리 업로드와 링크 스티커 추가는 고객이 직접 합니다. 공유 보상과 게시 여부 검증은 없습니다.
- 공식 로고와 글꼴은 로컬에서 제공하며 외부 추적 스크립트는 포함하지 않습니다.
- 1차 버전 디자인과 참여 규칙은 고정입니다. 경품 이미지 업로드, 날짜별 경품 배분, 변경 감사 로그, Shopify 자동화는 다음 범위입니다.

## 주요 파일

- `public/`: 고객 화면, 관리자 화면, 공유 이미지 생성
- `api/index.js`: Vercel API 및 인증
- `lib/event.js`: 서버 추첨·참여·관리 기능
- `lib/db.js`: PostgreSQL / 로컬 SQLite
- `server.js`: 로컬 실행
- `test/event.test.js`: 경합·재고·재응모·날짜·수령 정보 검증

Vercel 및 PostgreSQL 설정 참고: https://vercel.com/docs/project-configuration/vercel-json · https://node-postgres.com/features/transactions
